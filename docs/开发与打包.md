# 开发与打包

## 1. 运行环境

本项目以本地网页完成数据处理，桌面程序使用 pywebview 和系统 WebView2 提供独立窗口。文件在浏览器内的 Pyodide 环境中处理，不经过远程服务，也不需要数据库。

验证环境为 Windows、Python 3.13.5、openpyxl 3.1.5、pytest 9.2.0、pywebview 6.2.1。桌面构建依赖以 `requirements-desktop.txt` 为准，测试与数据脚本依赖见 `tests/requirements.txt`。

以下命令均在项目根目录执行：

```powershell
Set-Location -LiteralPath 'E:\毕业设计3\project8'
```

## 2. 安装开发依赖

首次创建开发环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r tests/requirements.txt -r requirements-desktop.txt
```

`.venv/` 为本机开发环境，已在 `.gitignore` 中排除。复制到另一台电脑后可按命令重建，不把当前环境当作项目运行库分发。页面使用的运行库另存于 `vendor/`。

## 3. 运行源码

浏览器方式只需 Python 标准库：

```powershell
python run_local.py
```

访问 <http://127.0.0.1:8000/index.html>。按 Ctrl+C 停止服务。`run_local.py` 固定使用 8000 端口，若已占用，先关闭占用该端口的旧服务。

桌面源码方式：

```powershell
.\.venv\Scripts\python.exe desktop.py
```

桌面入口自动选择空闲端口，并在窗口关闭时结束资源服务。

## 4. 验证

全套测试，包括学生工具与保留的通用接口：

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

只运行学生工具的 33 个测试方法：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_student.py -v
```

全套测试当前报告为 170 项及 11 项子测试通过，二者统计范围不同。桌面自检会实际操作窗口并保存结果包：

```powershell
.\.venv\Scripts\python.exe desktop.py --self-test E:\毕业设计3\project8\output\desktop\源码检查.json
```

测试模式使用隐藏窗口，记录路径应为绝对路径。自检结束后读取 JSON 中的“检查状态”，不能只看进程是否退出。

## 5. 构建 EXE

使用单独的构建环境：

```powershell
python -m venv .build-venv
.\.build-venv\Scripts\python.exe -m pip install -r requirements-desktop.txt
.\.build-venv\Scripts\python.exe build_desktop.py
```

构建入口为 `desktop.py`，输出为上一级目录的 `学生信息脱敏工具.exe`。命令执行成功后会替换该路径的同名 EXE，需要留存旧版本时先将旧文件另存。

构建脚本递归收集 `js/`、`py/`、`css/`、`static/` 和 `vendor/`，附带三份内置表格及许可文件。`desktop_app/` 沿 Python 导入关系收集；开发环境、公开数据原件和既有处理结果不进入程序资源。

重新构建后检查实际产物：

```powershell
& '..\学生信息脱敏工具.exe' --self-test E:\毕业设计3\project8\output\desktop\新构建检查.json
```

程序体积约 20 MB。交付目录中的现有 EXE 为前一构建版本，当前源码的模块更新需重新构建后生效。

## 6. 修改模块时的对应位置

| 修改内容 | 需要同步的文件 |
| --- | --- |
| 字段别名 | `py/student_tool/constants.py`、相关字段测试、使用说明 |
| 默认保留位数 | `py/student_tool/rules.py` 与 `js/ui/rules.js`、数据说明 |
| 新字段类型或处理方式 | Python 类型与校验、单元格处理、`js/config.js` 和配置表 |
| 新增 Python 模块 | `js/worker/runtime.js` 的源码清单、`sw.js` 的应用资源清单 |
| 新增页面 JavaScript 模块 | 引用它的入口、`sw.js` 的应用资源清单 |
| 行处理或残留检查 | 对应行为测试、使用说明和测试报告 |
| 文件保存或窗口行为 | `desktop_app/`、桌面自检和 EXE 实际检查 |

应用代码在本机服务中优先读取新内容；固定版本的第三方库优先使用缓存。若调整了资源清单或部署方式，应检查 `sw.js` 的缓存版本与实际文件是否一致。

## 7. 数据维护脚本

以下命令会写入数据文件，应与只读验证命令分开使用：

```powershell
.\.venv\Scripts\python.exe sample_data/generate_students.py
.\.venv\Scripts\python.exe sample_data/process_students.py
.\.venv\Scripts\python.exe public_data/prepare_data.py
```

第一条重建学生表与异常表；第二条重建内置脱敏结果和人工核对清单，已填写的人工结论需要先保存；第三条从现存公开原件重新整理导入表和对照结果，不执行网络下载。

测试记录保存于 `output/`，验证结果和适用范围见 [测试报告](测试报告.md)。
