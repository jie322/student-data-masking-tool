# 源码阅读与设计实践指南

本指南面向评审专家、指导教师及后续二次开发人员，旨在阐明系统的工程架构设计理念、设计模式应用、核心数据流转链路与关键算法实现。

---

## 一、系统代码规范与注释约定

工程全量源码遵循统一的学术与工程注释规范，采用“自顶向下、意图先行”的文档化注释标准：

- **模块级 Docstring**：明确定义模块在系统架构中的单一职责、上下游依赖与设计边界；
- **函数/方法 Docstring**：遵循标准格式（PEP 257 / JSDoc），详尽描述入参契约（Args）、返回值结构（Returns）及可能抛出的异常类型（Raises）；
- **核心逻辑与边界注释**：对关键算法分支、安全防御机制、位运算及数学校验（如 ISO 7064:1983.MOD 11-2）阐明设计意图与合规依据；
- **零敏感泄露约定**：日志与调试输出严禁打印单元格敏感原值或私有文件系统路径。

| 文件类型 | 规范约定 | 核心职责说明 |
| --- | --- | --- |
| Python 核心 (`py/student_tool/*.py`) | PEP 8 + 规范中文 Docstring | 表格只读解析、智能别名推断、掩码脱敏流水线与全表安全审计 |
| 前端驱动 (`js/**/*.js`) | ES Modules + JSDoc | 响应式交互、Worker 沙箱 IPC 通信编排、内存 Blob 生命周期管理 |
| 视窗容器 (`desktop.py`, `desktop_app/`) | 模块化生命周期设计 | 轻量环回静态服务拉起、WebView2 原生视窗挂载与 Win32 保存对话框桥接 |

## 二、架构设计模式与工程实践

系统在实现过程中综合运用了现代软件工程中的经典设计模式与安全原则：

### 1. 外观模式 (Facade Pattern)
- **典型实现**：`py/student.py` 作为顶级聚合外观入口，将 `student_tool` 子系统内部的常量规范 (`constants.py`)、解析器 (`readers.py`)、掩码算法 (`masking.py`)、流水线编排器 (`processor.py`)、安全防御模块 (`safety.py`) 与写出器 (`exporters.py`) 统一封装并暴露标准化接口，简化了 Web Worker 与自动化测试的调用契约。

### 2. 流水线与过滤器模式 (Pipeline-Filter Pattern)
- **典型实现**：`py/student_tool/processor.py` 中的 `process_tables()` 方法构建了一条清晰的数据处理流水线：
  $$\text{输入规整} \longrightarrow \text{配置校验} \longrightarrow \text{行宽与唯一性检查} \longrightarrow \text{单元格掩码清洗} \longrightarrow \text{公式转义} \longrightarrow \text{全表残留深度审计} \longrightarrow \text{条件持久化写出}$$
  各过滤器职责明确、高内聚且易于单独进行单元测试覆盖。

### 3. 沙箱隔离与最小特权原则 (Principle of Least Privilege)
- **典型实现**：`js/worker/network.js` 与 `js/worker/runtime.js` 对 Web Worker 沙箱环境进行访问控制拦截，杜绝向外部任何公网发起请求，所有运行库与纯 Python Wheel 均从本地受控白名单目录离线载入。

## 三、核心业务调用链路剖析

### 1. 前瞻样本预览调用链 (Preview Flow)

```text
[UI 层] 用户点击“预览脱敏效果”
   │
   ▼
[流程层: js/main.js] 触发事件监听器，调度 processing.js -> previewResults()
   │
   ▼
[通信层: js/services/engine.js] 向 Web Worker 发送 request("student-preview", payload, [buffer])
   │
   ▼
[沙箱调度: js/worker/student-handler.js] 挂载至 MEMFS，调用 Python student.preview_file()
   │
   ▼
[解析与切片: py/student_tool/processor.py] 抽取各表前 10 行样本数据
   │
   ▼
[单元格算法: py/student_tool/masking.py] 执行 normalize_phone / valid_identity / mask_value
   │
   ▼
[安全审计: py/student_tool/safety.py] 执行 safe_cell 公式转义与 scan_output 残留排查
   │
   ▼
[视图呈现: js/ui/results.js] 接收结果并在内存中惰性渲染前瞻数据表格与指标看板
```

### 2. 全量批量脱敏与安全导出调用链 (Batch Processing & Export Flow)

```text
[UI 层] 用户点击“开始批量脱敏”
   │
   ▼
[流程层: js/features/processing.js] 调度 processFiles()，锁死交互状态
   │
   ▼
[沙箱计算: py/student_tool/processor.py] 触发全量数据流水线，执行整表扫描
   │
   ▼
[写出过滤: py/student_tool/exporters.py] 审计通过后，全新流式构建 XLSX / UTF-8 BOM CSV
   │
   ▼
[前端组装: js/features/processing.js] 利用 JSZip 在客户端内存打包脱敏表格与合规审计报告
   │
   ▼
[系统保存: js/services/downloads.js] 浏览器触发虚拟下载 / 桌面端通过 DesktopApi 弹出原生保存窗口
```

## 四、关键核心数据结构与契约规范

### 1. 列脱敏规则规范对象 (`RuleSpec`)
在前端与后端计算引擎之间流转的列规则配置字典结构如下：

```json
{
  "type": "phone",         // 字段语义类别：phone, email, identity, name, identifier, address, text, other
  "mode": "mask",          // 脱敏模式：keep(保留), mask(部分遮盖), full(完全隐藏), drop(整列删除)
  "prefix": 3,             // 前缀明文保留字符数 (0 ~ 6)
  "suffix": 4,             // 后缀明文保留字符数 (0 ~ 6)
  "keep_domain": false,    // 电子邮箱专用：是否保留 @ 后的域名后缀
  "required": false        // 必填完整性校验开关：开启后空值将触发 missing 异常
}
```

### 2. 批处理审计统计与告警结构 (`AuditRecord`)
```json
{
  "summary": {
    "input_rows": 100,      // 导入原始行数
    "output_rows": 100,     // 候选导出有效行数
    "masked_cells": 900,    // 实际执行掩码处理的单元格总数
    "anomaly_rows": 0,      // 包含格式或必填异常的行数
    "skipped_rows": 0,      // 异常策略下被隔离剔除的行数
    "residual_cells": 0,    // 检出的敏感明文残留数（必须为 0 方可放行导出）
    "formula_cells": 0      // 触发单引号注入转义的潜在公式单元格数
  },
  "issues": [
    {
      "sheet": "数据表1",
      "row": 15,
      "column": 3,
      "code": "format",
      "reason": "字段格式异常，已隐藏原值"
    }
  ],
  "blocked": false          // 熔断阻断标志位
}
```

## 五、安全防御与合规算法机制

1. **GB 11643-1999 身份证双重校验**：
   - 提取出生日期切片进行公历日历有效性验证（拦截 2 月 30 日、13 月等伪造格式）；
   - 执行 ISO 7064:1983.MOD 11-2 模 11 加权校验和算法计算校验位，支持大小写 X 兼容。
2. **脱敏幂等性保护机制 (`already_masked`)**：
   - 识别符合当前前后缀掩码规则的现有值，杜绝二次重复处理导致 `***` 嵌套或信息失真。
3. **公式注入 (CSV/Excel Formula Injection) 防御**：
   - 拦截以 `=, +, -, @` 开头的非纯数值单元格，强制注入前导单引号 `'`，使 Microsoft Excel 与 LibreOffice 严格将其作为静态文本呈现，杜绝 DDE 或宏脚本远程执行风险。
4. **多模式字典与正则双轨敏感残留扫描**：
   - 在数据写出前，将批次内标记为敏感列的所有明文提取为临时安全字典，结合手机、身份证、邮箱高精正则，对全量数据行执行跨列跨表交叉检索，杜绝敏感信息复制至未脱敏备注列导致的暗流泄漏。
